# 附件逐项采纳及边界

请求依据：包内`evidence/user_direction.txt`，以及已交付的在线pilot复盘。附件中对实验概念、数值及潜在理论机制的区分保留。

| 附件建议 | 本版处理 | 未声称的内容 |
|---|---|---|
| 根据汇合完成价值而不是仅最长单分支 | ready分支按共享汇合、共享前缀分组，生成部分嵌套关键子集；完整rollout裁决 | 不是把静态tail当真实完成时间或硬编码B3/B4 |
| 缓存收益和所有workflow干扰一起计算 | 沿用原生cache证据、共同事件模型和全体未完成workflow代价 | 不把命中token当GPU毫秒，不认定模型真实最优 |
| 额度基于候选放置后的状态 | post_budget对每个完整方案重新构建prefill/decode/context集合 | 不由动作前队列计数直接指定必胜预算 |
| 允许不切换 | 显式保留fixed与current，数值同分时优先少切换 | 不把预算切换次数作为优化目标 |
| 少而完整、及时返回 | 默认3个在线调度包，Joint优先1个交叉，坐标及追加交叉均受同一deadline；worker提前停止 | Decoupled拥有相同总deadline，不保证所有候选被穷尽 |
| 不混淆模型错误和执行成本 | 用已有数据作整block留出的phase服务曲线选择；端到端计时不变 | 尚未得到真实未执行动作标签或新实机收益 |
| 证明DAG信息自身增量 | 代码不依赖分支名，保留角色重命名/依赖测试 | 本轮五方法不是DAG信息屏蔽实验；后续需单独对照 |
| best fixed应调优 | 本轮明确标注1024为回归参照 | 不用旧扫描宣称新版本已优于最强固定策略 |

联合选择面对的仍是同一问题：哪些请求值得推进、会影响哪些其他workflow，以及应在哪个副本以什么prefill节奏推进。提案库中的压力规则只提出候选，不替代统一JCT目标。

## 未纳入本包的外部资料结论

本次实现依据附件和可用源码，没有重新复现Preble、Sarathi-Serve等外部系统。附件链接仅作为其文字来源背景，不把外部系统的收益转移为本方法的收益。积极向量的数值只作为此前具体机制协议的回归夹具；它不是所有在线状态的固定动作。
