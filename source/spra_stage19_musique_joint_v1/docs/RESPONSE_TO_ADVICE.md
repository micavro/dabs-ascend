# 对本次附件的处理

附件提出的是设计建议和对历史汇总的解释，不当作新实机标签。历史TPOT、mixed步时、Stage18合成负载结论按用户材料保留，本包没有再凭汇总定位新后端bug。

| 建议 | 本次处理 | 边界 |
|---|---|---|
| 找一个真实workflow数据集 | 选择官方MuSiQue-Ans v1.0，用原标注依赖与真实文本逐hop执行 | 研究数据集本身由单跳问题组合，不是生产调用trace |
| Joint可以提前知道workflow结构 | 静态编译原图、反链、汇合与子问题模板 | 标注分解为显式特权信息；未知生成答案和未来长度仍估计 |
| 真实父输出进入子输入 | 原生#位置绑定到实际LLM回答，完整父响应也进入子prompt | 格式或答案错误不teacher forcing修复，全部计入质量 |
| 独立prefill分配而非token比例 | 硬total4096不再作为单独搜索轴，候选含放置、准入、顺序、每副本cap | 未新增backend任意逐成员chunk API；仍由原生调度器执行 |
| 保护当轮decode | local mixed-step候选筛选与比较后保护 | 服务模型和1ms余量为近似，不是误差界 |
| 保护后续decode并发 | 完整因果rollout继续模拟prefill转decode，并检查已有decode预计剩余完成 | 自然输出长度来自开发生成先验，实际TPOT只能实测验证 |
| 离线编译、在线轻量化 | DAG与输入证据静态处理提前；在线只比较一个有意义的2×2邻域 | 未实现由真实反事实标签学出的离线policy table；仍有有限在线4候选评价 |
| 比较联合动作而非开关次数 | Joint四格同状态评价，Decoupled在同一四格空间顺序选择 | 有限邻域不是全局最优，Joint可能保留参照 |
| TTFT/TPOT质量与JCT并报 | 请求级、节点完整首内容、TPOT代理、完整JCT、EM/F1、实际工作量 | 不合并错误口径，不扣时间，不把错误率增加称为加速 |
| 强fixed与独立测试 | 新数据train选择fixed与服务曲线，dev五方法运行前冻结 | 4block是开发结果，不是统计非劣或普适10%证据 |

## 不采用的捷径

不重跑旧合成pilot来充当真实数据；不把MuSiQue问题文本仅用作随机token种子；不从支持标签挑正确段落；不把错误父回答换成标准答案；不把全部输出强制为相同长度；不拿另一条trace的绝对动作时刻照搬。

允许读取标注问题分解并非偷偷泄漏答案；但它比只有最终问题的未知规划场景信息更强。论文必须明确known-plan条件，不能与原始端到端/未知分解排行榜直接比较。
