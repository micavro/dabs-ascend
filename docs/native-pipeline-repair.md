# 1610 观测、候选和评分链路修复

## 已知证据与结论

用户复制的 1610 前 8 条摘要显示工作量/DAG 完成，但规划验收未通过。R4_L8 的 Ours 有 75 次 proposal 调用，74 次没有不同可执行候选；仅一次生成候选，参考评分因 `p:3` 越界中止。R2_L16 对应 400/399/1，参考评分因 `pc:3200` 中止。另有真实在途批次触发 `p:1`、`pc:3199`。这与单纯“80 ms 起点错了”不同：260d875 已经使用三个绝对截止时间的最小值，剩余问题涉及预算、可执行机会、证据覆盖和模型支持。

以上依据复制内容，不声称重新独立审计现场全部原始日志。计数之间可能重叠，不能相加作为总失败数。没有候选也可能完全合理：没有压力差、客户端上限已满、缺少可变队列对象或未知缓存。不得放宽这些条件制造成功。

## 具体修改

| 环节 | 修改与保持的边界 |
|---|---|
| 观测/预测 | `native_client` 分开记录 `native_observation_errors` 和 `native_prediction_errors`。模型越界只使预测时长未知，不抹掉实际请求进度、队列、物理容量和缓存观测。RR/SLL/Ayo 不因此申请不必要的观测回退；Ours 不能对未知在途时长填零，保留参考动作并记录原因。实际观测过期或请求映射竞态仍回退。 |
| 查询范围 | 同样的 8 前缀、8192 token/副本预算，四种方法共用。按临时参考准入集合、原 DAG tail 排序查询，避免 FIFO 前缀把关键候选挤出预算。上一轮压力只用于选择本轮询问对象，不能用来证明本轮状态或直接执行动作。每次仍向引擎查询真实驻留。 |
| 短前缀 | 原 16-token 共享前缀不足现场 128-token 块，原逻辑一直不查询。现在以一个真实 token 查询引擎，获得零完整块的事实证据；不凭空把未知填成 miss，也不声称有整块命中。 |
| 身份缓存 | 仅缓存 `(namespace, 实际 token 前缀)` 的输入身份散列；输入或 namespace 改变立即失效。不缓存跨决策驻留状态。 |
| 控制开销 | 原始 RPC 临时缓存在单事件循环，动作提交后再紧凑写出。历史批次采集放到下一决策窗口前，错过的固定周期跳过，不给旧动作延期。状态只去掉提示词、回答等评分不使用的元数据，完整 216 节点和后继仍传输。 |
| 评分开销 | 本轮 cache-token 索引代替反复线性搜索；保守驱逐模型在原条件已证明无需驱逐时不排序。完整滚动事件和目标不裁剪，1024/128 与 4096/16 路径作等价比较。 |
| 范围检查 | 合并多个 decode 步时检查首尾上下文，不能只检查第一个步。范围错误记录副本、阶段、字段、请求值和实测训练范围。 |
| 日志 | `decisions.jsonl` 不再重复整个原始 RPC，保留快照身份/序号/时间用于关联 `native_events.jsonl`。保留预测失败、观察/整理/分派/评分耗时、候选和完整评分计数。`copy_logs/COPY.txt` 持续追加精简摘要。原始批次持久落盘后才 ACK 引擎；写盘失败不能删除引擎记录。 |

规划仍为 `min(规划开始+80ms, 固定窗口截止-25ms, 最早快照截止-25ms)`。主机 IPC、状态整理及队列等待是真实开销，未增加新租期。200 ms 有限优先级窗口、到期 FIFO、Decode/5 秒年龄保护、Ayo 保守 KV 预留口径均未改。零偏离、负收益、回退和失败继续保留。

## 新标定覆盖

原模型按阶段训练，但旧覆盖检查把不同阶段合并检查最大值。另一阶段的较大上下文不能证明当前阶段覆盖；整体样本很多仍可能漏掉 1/3-token 尾块或部分缓存后的高上下文。

新计划 `r234_phase_tail_prefix_v1` 保留原 14 种负载，增加 11 种预先确定的边界负载，每副本各 25 组 train/holdout。新增 1/3-token 输入，3585/3587-token 输入与 512-token 部分前缀预热，3968-token 高上下文锚点及 640-token 部分缓存。并发 3 的边界组依次等待真实一个、两个 decode，再提交短尾/部分缓存请求。没有修改服务 max_num_seqs、1024 步预算或 128 块大小。

新种子与旧计划、训练与留出之间分别分离；不借用正式实验结果拟合。每副本每阶段仍要求两份各至少 20 个合格独立批次；p95 相对误差 <= 0.35、RMSE/留出均值 <= 0.25 均不变。额外要求每个阶段在各自 train 和 holdout 中覆盖声明的尾块/上下文边界，不能借另一阶段或另一份数据满足。`native_gate` 从原始事件重建样本和验证结果，不信 `pass` 标志。

这些边界是最低覆盖要求，不是手填的回归范围。实际预测范围继续由该副本该阶段的训练样本 min/max 冻结；新计划若未实际采到边界、误差失败或运行遇到更极端范围，仍失败并给出具体字段。每组只更新采集进度，结束后拟合一次，避免每组反复做全部 NNLS。

计时对象保持已有 `async_host_completion_accounting_v1`：非重叠的主机完成区间累计开销，属于吞吐代理模型。仍明确 `host_step_equivalence=false`、`original_gpu_timing_equivalent=false`，不是 GPU 原来同 batch step、NPU forward 或 HTTP TTFT。新覆盖不解决这个口径差异，也不将其伪装为等价。

## 现场部署与判断

这次没有修改 `dabs_native/` 或服务补丁，已加载现场适配器不需安装/重启。旧机制证据若仍对应当前服务可以复用；旧标定覆盖不足需要新标定。`verify --input` 自动检查当前服务并执行必要的新标定，然后原始证据复核、前 8 条条件和规划审计。若服务身份/资源已经变化，在长标定前停止，不能用旧探针证据。

README 顶部提供当前两条命令。新实验在新目录；规划协议标识更新为 `bounded_native_observation_prediction_v3`，禁止续接 1609/1610 结果。验证通过后 `experiment` 续跑已验证的新实验，不重复前 8 条。正式 96 条件顺序、四方法、DAG、工作量、种子没有变。

验收看完整参考/不同可执行候选评分是否在时限内完成、真实动作回执及工作量，不要求非参考胜出。控制流程 CPU 用例通过仅证明实现的可执行性与回归条件；现场模型误差、观察耗时、评分预算、候选机会和 NPU 结果尚待新运行确认。
