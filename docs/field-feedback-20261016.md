## 代码处理

1. `deployment_records` 只保存白名单容器状态：状态名、退出码、OOM、启动/退出时间、暂停/重启/死亡标记、重启次数；继续排除 Docker Env 和原始命令。
2. `prepare` 在原采集步骤加入默认 300 秒健康等待。仅对选中、运行且映射正确的容器探测 HTTP；停止、暂停、重启中或映射错误时落盘退出，不自动启动服务。
3. `inspect` 默认立即检查，也可加 `--wait-ready 300`。运行但尚未就绪的服务仍尝试采集包元数据和源码；停止的容器跳过 exec，避免把服务状态错误误报为解释器问题。
4. 未就绪服务保留最近启动的筛选日志，包含 Docker logs 的 stdout/stderr。摘要只列最后 12 行，详细文本放 `service_logs/`。日志不能当成完整故障证据；未匹配或含凭据/请求内容的行会被省略。
5. 每轮健康与状态写入 `readiness.jsonl`。失败仍写 `inspection.json`、`SUMMARY.txt`，不打包，不上传。
6. 采集及实验 `environment.json` 分开记录服务批次预算、最大序列数、上下文长度，以及控制器假设、客户端并发。当前 1024 与 4096 的预算差异明确可见，未据此修改算法或服务配置；仍不宣称原生机制已验证。
