# 1609 Ours 无候选/评分：控制端修复

## 事实与原因

1609 前 8 条件均完成固定工作量和依赖检查；两条 Ours 分别记录 51、183 次 V5 决策，候选/候选完整评分/非参考选择/引擎非参考应用均为 0。抽样观察约 110 ms；该抽样不能当作所有决策的耗时分布。

旧 runner 在 `native.observe()` 前记录 `now`，却以 `now + 80ms` 作为搜索截止时间。观察返回后进入 V5 时预算已经用完，其入口直接返回参考动作。这不能解释为“完整比较之后 Ours 认为参考最优”。

## 实际代码改动

- `native_planning.py` 在观察和基线准备之后计算 `min(当前时刻+80ms, 固定周期截止-25ms, 最早快照过期-25ms)`。给同机 worker 传绝对 monotonic deadline，IPC 与排队同样消耗预算；不会让旧计划得到新的租期。
- `r234_run.py/r234.py` 在正式到达计时前预加载派生的 V5、语义选择器和评分器。传给 worker 的视图去除重复的原始 RPC/前缀 token 数据，完整工作流节点、DAG、缓存证据、资源、进度和在途批次保留。
- `native_scoring.py` 的保护检查只复制其会修改的节点标量，不重复深拷贝嵌套 DAG。`native_algorithms.py` 对同一虚拟时刻的 common-continuation 缓存偏好、目标负载和保守预留量作局部复用；每次准入后失效目标选择。没有跳过事件、请求、工作流或后继。1024/128 与 4096/16 的完整 216 节点滚动结果逐字段比较（包括缓存驱逐/失效、准入和全部事件）一致，仅 CPU 耗时除外。
- 过滤原生投影后只改变跨副本全局列表顺序、或仅改变未准入请求放置的候选。这些变化不改变真正可执行动作，不应算可比较候选。冻结的同一准入集合、纯路由/纯排序、压力/缓存条件及增益阈值保留。
- 模型范围外的 guard 拒绝当前候选并保留先前完整评分；不再让异常把整个结果清空。模型支持范围、Decode 保护、年龄保护和收益阈值不变。
- 迟到搜索结果作为诊断保留，不应用；汇总引擎效果时也跳过这些记录，避免迟到非参考结果被误算、或因没有 `reference_action` 报错。

原始源码及清单没有修改。独立转换规则写入 `native_transformations.json` 便于核对。本次未修改 `dabs_native/`、安装补丁或服务接口，不需要更新已加载的服务端适配器。

## 仍然可能没有候选/完整评分的正当原因

冻结 V5 在没有 ready 节点时不搜索；路由候选要求源副本的具体缓存证据已知、压力差达到原阈值，还要保持相同准入集合。client-inflight=2 满载、可变队列没有可交换对象、源缓存未查询/已过期，都可能没有合法不同动作。未知缓存不填 0。投影过滤这些动作是执行语义要求。

完整评分仍需模拟整个剩余 DAG，早期大快照可能超过 80 ms 内分配到的单次评分预算。没有延长到下一周期，也没有裁掉未完成节点或用部分评分当分数。本机性能诊断确认重复的 continuation 计算是主要开销之一，已减少；这不保证每次大快照都能在现场预算内完成。必须用新现场记录判断评分覆盖，不能把 CPU 小样本通过当现场通过。

`v5_stop_reason` 区分预算不足、无合法差异候选、观察不可用、参考未完成、候选未完成、参考保留和非参考选中；`candidate_diagnostics` 记录缓存未知、准入集合变化、无实际效果和范围外保护拒绝。评分失败原因为 `cpu_deadline`、模型范围外等，保留完整原始评估。`diagnostic_reasons.csv` 和复制摘要都能查看。

## 现场验证与续跑

README 顶部提供两条命令。`verify --input 旧native_test目录` 只读复制普通原始证据，在新目录复核当前服务与冻结模型，运行原计划前 8 条（可设 12 等完整方法组），再检查原始 `decisions.jsonl`。没有重新采样、安装、重启或清缓存。

`planning_audit.json` 要求每条 Ours 至少存在一次同一决策中、窗口内、未回退的完整参考评分与不同可执行候选的完整评分。必须有真实 scorer 的有限数值、完整滚动原因和 worker 完成时刻。迟到结果、只有生成数量、部分评分、NaN、相同动作和手填 PASS 均不能满足它。它是新增的规划覆盖检查，不替代既有原生/工作量/标定验收。Ours 不胜出可以通过；没有合法机会会显示“覆盖未证明”，不会伪造一个候选放行。

`experiment` 重新核验后续跑这个正常暂停的实验，保持原 96 条顺序、种子、工作量、模型、服务和资源。前 8 条不重跑。旧 1609 采用不同规划语义，不能拼接；协议记录 `post_observation_bounded_planning_v2`，这是实验方法一致性检查，不是文件哈希部署门禁。旧结果不改动。

## 集中复制日志

`copy_logs/COPY.txt` 为普通 UTF-8 文本，运行中追加；同一实验续跑沿用该文件。`bash run_native.sh logs` 定位最新摘要，无需找嵌套文件。`STEP/GATE/CONDITION/P/D/RECEIPT/C/ERROR/END` 分别表示步骤、验收及资源、条件、30 秒进度、决策样例、最终回执样例、条件汇总、错误、结束。

重复决策原因最多 3 个样例，完整计数每 30 秒及条件末更新。D 中 scores 是 `[候选编号,是否完整,预测代价ms,原因]`；已评分/被选择/引擎应用分开统计。不给 prompt/token 数组、重复栈或装饰分隔符。原始 JSONL 不删、不精简，只有复制用摘要压缩；失败和负收益保留。摘要不能独立替代原始验收证据。

## 测试范围

CPU 回归覆盖观察 110/115 ms 后的预算、绝对 deadline/IPC 迟到、实际 V5 合法候选完整评分、未知缓存、容量不放宽、范围外 guard 保留评分并拒绝候选、完整 216 节点滚动等价、迟到/部分/相同候选误放行，以及新验证入口和续跑链路。CPU double 不计原生机制证据。现场待验证项是新规划覆盖、实际队列/路由回执、完整 96 条工作量与性能；不要求正收益。
